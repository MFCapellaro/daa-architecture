# Capabilities

## Purpose

Capabilities define observable abilities that emerge from coherent relationships among functions within the First Corpus.

A capability is not an isolated function.

A capability emerges when multiple functions interact coherently to produce an operational ability that can be observed, recognized, or exercised by a system.

---

## Methodological Position

Capabilities follow functional relationships.

```text id="kq7r5n"
Source
  ↓
Observation
  ↓
Normalization
  ↓
Convergence
  ↓
Divergence
  ↓
Function
  ↓
Functional Relationship
  ↓
Capability
```

Capability is therefore an emergent layer.

It is not assigned directly from product names, manufacturer terminology, or individual characteristics.

---

## Core Principle

> **Capability is the observable expression of coherent functional interaction.**

A capability does not belong to a single function.

It belongs to the coherent organization of functions.

---

# Function and Capability

The Corpus preserves the distinction.

### Function

A function describes an operational role.

```text id="d9p2hc"
Obstacle Detection
```

### Capability

A capability describes an observable ability emerging from related functions.

```text id="f7a3qx"
Adaptive Obstacle Response
```

The relationship may be represented as:

```text id="x8c1zm"
Functions
   ↓
Relationships
   ↓
Functional Composition
   ↓
Observable Ability
   ↓
Capability
```

---

# Capability Emergence

A capability requires more than the presence of functions.

```text id="t5z8q4"
Function A
+
Function B
+
Function C
        ↓
Coherent Interaction
        ↓
Operational Result
        ↓
Capability
```

The operational result must be observable.

Therefore:

```text id="m7v2yk"
Potential Capability
        ↓
Observable Behavior
        ↓
Capability
```

---

# Capability Structure

Each capability should eventually contain:

```text id="8m3v1p"
Capability
├── Definition
├── Purpose
├── Constituent Functions
├── Functional Relationships
├── Operational Context
├── Observable Expression
├── Supporting Evidence
├── Convergence
├── Divergence
├── Evidence Status
└── Open Questions
```

This structure maintains traceability to the evidence.

---

# Capability Conditions

A capability should satisfy four preliminary conditions.

## 1. Functional Composition

Multiple functions participate in the capability.

```text id="9w6b3a"
Function
+
Function
+
Function
```

---

## 2. Coherent Relationship

The participating functions are related in a meaningful operational structure.

```text id="j2k8x4"
Function
   ↓
Relationship
   ↓
Function
```

---

## 3. Observable Result

The composition produces an observable operational ability.

```text id="r4c9m1"
Functional Composition
        ↓
Observable Result
```

---

## 4. Contextual Meaning

The ability has meaning within an operational context.

```text id="z7p5s2"
Capability
    +
Context
    ↓
Operational Meaning
```

Without context, the capability may be incorrectly generalized.

# Capability Candidate 01

## Autonomous Operation

### Definition

The ability of a system to execute an operational sequence with reduced or delegated direct human control through coordinated navigation, planning, control, sensing, and movement functions.

### Constituent Functions

Current candidates include:

```text id="x3q7lm"
Positioning
Navigation
Path Planning
Movement
Obstacle Detection
Obstacle Avoidance
Control
```

### Functional Relationships

```text id="s9w2kc"
Positioning
     ↓
Navigation
     ↓
Path Planning
     ↓
Control
     ↓
Movement
```

with environmental adaptation:

```text id="g6p1za"
Obstacle Detection
        ↓
Decision / Response
        ↓
Obstacle Avoidance
        ↓
Movement Adaptation
```

### Observable Expression

The system performs an operational sequence without requiring continuous direct control of each movement decision.

### Evidence Status

**Capability Candidate**

### Important Distinction

Autonomous Operation must not be inferred merely because a manufacturer uses the term "autonomous."

The capability requires evidence of coordinated operational behavior.

### Open Questions

* What degree of human supervision remains compatible with autonomy?
* Which functions are necessary?
* Which functions are optional?
* Is autonomous operation one capability or a family of capabilities?

# Capability Composition

Capabilities may themselves participate in larger operational structures.

For example:

```text id="q8x2mf"
Autonomous Operation
        +
Agricultural Liquid Treatment
        +
Adaptive Obstacle Response
        ↓
Autonomous Agricultural Treatment
```

This is currently a **higher-order capability candidate**.

The Corpus should not introduce it as a stable capability until sufficient evidence establishes that the constituent capabilities operate coherently as a combined ability.

---

# Capability and Purpose

# Capability and Context

Capabilities are contextual.

```text id="x4v8kp"
Function
    ↓
Relationship
    ↓
Capability
    ↓
Context
```

A capability observed in an agricultural drone should not automatically be generalized to every domain in which similar functions occur.

Context establishes meaning.

   ┘

# Capability Divergence

# Capability vs Characteristic

A capability must remain distinct from its measurable characteristics.

Example:

```text id="a7k2pm"
Payload Capacity
      ↓
Characteristic
```

while:

```text id="b9x4qr"
Agricultural Material Treatment
      ↓
Capability
```

A characteristic may constrain a capability without defining the capability itself.

---

# Capability vs Product

A product provides or expresses capabilities.

```text id="w2m6ys"
Product
   ↓
Capabilities
   ↓
Operational Ability
```

The product is therefore an implementation context.

Capability is an emergent operational property.

---

# Capability vs Product Class

Product Class remains downstream.

```text id="v8r1ct"
Capabilities
     ↓
Capability Structure
     ↓
Recurring Pattern
     ↓
Product Class
```

Products should be grouped into Product Classes only when their capability structures show sufficient coherence.

# Capability Evidence Levels

## Level 1 — Potential

Functions suggest that a capability may exist.

```text id="m4q8zf"
Functions
   ↓
Potential
```

---

## Level 2 — Candidate

Functional relationships provide a coherent hypothesis.

```text id="n7s2wb"
Functions
   ↓
Relationships
   ↓
Capability Candidate
```

---

## Level 3 — Observed

The operational ability is directly evidenced.

```text id="x1p6ka"
Capability
   ↓
Observed Behavior
```

---

## Level 4 — Corroborated

The capability is observed through multiple independent sources or implementations.

```text id="r5c9vm"
Evidence A
Evidence B
Evidence C
      ↓
Capability
```

---

## Level 5 — Stable

The capability demonstrates persistent coherence across products, families, or platforms.

This is the threshold for considering a capability part of the stable Corpus model.

# Open Questions

The current Capability layer leaves several questions open:

* What minimum composition defines a capability?
* When does a capability become observable?
* Can one function constitute a capability under certain contexts?
* Which capabilities are platform-independent?
* Which capabilities are manufacturer-specific?
* Which capabilities combine into higher-order capabilities?
* Which capability structures define Product Classes?
* Which capability signatures reveal manufacturer identity?

These questions remain open to evidence.

# Integrity

Capabilities must remain traceable to:

```text id="x7m2qc"
Source
  ↓
Observation
  ↓
Normalization
  ↓
Function
  ↓
Functional Relationship
  ↓
Functional Composition
  ↓
Observable Ability
  ↓
Capability
```

No capability should be defined solely by marketing terminology.

No capability should be inferred solely from the presence of individual functions.

No capability should be treated as a Product Class.

No capability should be treated as a characteristic.

---

## Core Principle

> **Capability is the observable expression of coherent functional interaction.**

Functions provide operational roles.

Relationships establish coherence.

Composition creates conditions.

Observable ability reveals capability.

The Capability layer therefore marks the point where the Corpus moves from describing what systems do toward understanding what systems are capable of doing.
