# System Views

## Purpose

System Views define how each actor perceives the Pool ecosystem according to their relationship with it.

A system does not have a single perspective. Each relationship reveals a coherent view of the whole.

## Guiding Principle

Every system view should preserve the identity of the whole while revealing the context of the relationship being observed.

## Zoom Levels

## Ecosystem View

The widest perspective.

Shows:

* global activity,
* regional patterns,
* collective capabilities,
* emerging opportunities.

This is the identity horizon of the system.

## Regional View

Shows:

* geographic concentration,
* local capabilities,
* services,
* events,
* opportunities.

Location becomes meaningful through relationships.

## Community View

Shows:

* groups with shared interests,
* experiences,
* knowledge exchange,
* complementary activities.

## Pool View

Shows:

* participants,
* supplier,
* offer,
* status,
* communication,
* metrics.

The collective relationship becomes visible.

## Individual View

Shows the contextual identity of each actor.

The avatar represents more than a profile:

* identity,
* context,
* capabilities,
* trajectory,
* relationships.

## Actor Views

## Participant View

Provides access to:

* active Pools,
* historical participation,
* learning opportunities,
* community knowledge,
* regional opportunities,
* related services.

## Supplier View

Provides access to:

* published offers,
* Pool activity,
* participant relationships,
* performance metrics,
* reputation evolution.

## Principle

Zoom is not only a navigation mechanism.

Zoom is a change in scale of understanding.
